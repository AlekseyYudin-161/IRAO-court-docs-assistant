# Судебные документы: учебный обезличенный набор

Версия 2 от 28.09.2026. Набор предназначен для разработки прототипа помощника для анализа документов из судов и документов ФССП.

## Состав

- `ocr/`: 23 PDF с судебными приказами и исполнительными листами.
- `fssp/`: 21 XML и 21 соответствующий PDF постановлений ФССП. Парные файлы имеют одинаковое имя без расширения.
- `labels/ocr.xlsx` и `labels/ocr.csv`: ожидаемые результаты для 23 судебных документов.
- `labels/xml.xlsx` и `labels/xml.csv`: ожидаемые результаты для 21 XML.
- `templates/`: пустые CSV с теми же столбцами для результатов прототипа.
- `manifest.json`: список входных файлов, количество страниц PDF и контрольные суммы.

Всего 44 PDF на 101 странице. У 28 PDF есть текстовый слой, 16 PDF содержат только изображения. CSV записаны в UTF-8 с BOM, разделитель - запятая; значения с запятыми заключены в кавычки.

## Как использовать

Обработайте входные PDF и XML и заполните соответствующий образец таблицы. Поля `Файл` и `FileName` содержат путь от корня набора. Таблицы в `labels/` позволяют сравнить результат прототипа с ожидаемым ответом. Это открытые примеры для разработки, поэтому оценка на них не заменяет проверку на новых документах.

Имена столбцов сохранены из исходных образцов, включая `отчетство`. Даты в CSV имеют формат `YYYY-MM-DD`; суммы указаны в рублях. Паспорта, ИНН, СНИЛС и номера дел следует обрабатывать как строки, сохраняя ведущие нули. Пустое значение означает отсутствие достоверно установленного значения в разметке. Оно отличается от числового нуля.

В OCR-таблице основная строка описывает должника, выбранного в разметке. Поле `соответчики_фио` перечисляет всех должников документа, включая основного; `соответчики_кол-во` содержит их общее количество. При одном должнике значение равно 1. ФИО в перечне могут быть записаны в том падеже, в котором они приведены в документе. Поле `дело_дата` содержит дату судебного акта по делу; дата выдачи исполнительного документа может отличаться. Судебные расходы без явного указания государственной пошлины не записываются автоматически в `дз_пошлина`.

XML-таблица содержит выбранные поля постановления. Полное дерево XML, повторяющиеся элементы и вложенные сведения об исполнительных производствах сохранены в самих файлах. Значения адреса и суммы в отдельных частях документа могут относиться к разным сущностям: текущему адресу должника, адресу из судебного акта, сумме взыскания или остатку задолженности.

В отдельных исходных документах встречаются противоречащие друг другу реквизиты одного лица. Если правильное значение нельзя установить по самому документу, такое противоречие сохранено с заменой обоих значений. Например, в `ocr_020` ИНН в карточке должника отличается от ИНН в цитате судебного акта. Таблица ожидает значение из карточки должника. Прототип может дополнительно отмечать такие расхождения для проверки сотрудником.

## Обработка данных и PDF

ФИО, идентификаторы физических лиц, номера дел и производств заменены учебными значениями. Даты и суммы преобразованы. Повторяющиеся лица и реквизиты обрабатываются согласованно между документами и таблицами. Города и названия улиц в персональных адресах заменены; короткие номера домов и квартир сохранены. В текстах могут оставаться наименования государственных органов, публичные коды судов и нормативные ссылки.

Для PDF сохранены количество, порядок и размеры страниц, расположение основных блоков, бланки и часть дефектов изображения. Чувствительные поля заменены на месте. В некоторых плотных блоках текст набран заново; шрифт и переносы могут отличаться. Подписи, печати с персональными реквизитами, штрихкоды и блоки электронной подписи удалены. На оборотах исполнительных листов закрыты участки с просвечивающими данными.

PDF созданы в новых контейнерах. Исходные вложения, служебные объекты и старый скрытый текст не перенесены. Текстовый слой, где он предусмотрен, сформирован заново. Сканированные страницы сохранены с разрешением около 216 dpi и сжаты JPEG.

Такая обработка влияет на сложность OCR. Набор сохраняет разнообразие форм и многостраничность, но не воспроизводит в точности сложность исходных сканов. Его нельзя использовать для утверждений о качестве распознавания необработанных реальных документов без отдельной проверки.

## Разметка и ограничения

При подготовке исправлены обнаруженные расхождения между документами и исходными таблицами: данные другого должника, адреса, даты, суммы и реквизиты. Для одного участника дела дата рождения в исходном скане не читается; в документе это указано явно, значение не выдумывалось.

Четыре повторяющиеся пары XML/PDF исключены. Четыре строки исходной XML-разметки без соответствующих входных файлов также исключены. Каждый оставшийся файл разметки ссылается на существующий документ.

Синтетические реквизиты не предназначены для поиска людей, проверки через государственные сервисы, расчёта возраста или проверки контрольных разрядов. Электронные подписи и юридическая подлинность документов не воспроизводятся. Совместимость XML с внешней XSD не подтверждалась; сохранение структуры проверено относительно исходных файлов.
